# Threat model

## Assets

- Hermes sessions and tokens (operator-level access to the agent).
- Conversation content, tool arguments and results, SOUL.md, skills, memory
  metadata, routines.
- Control of the agent-owned computer.
- The owner's attention: approvals must not train them to click through.

## Trust boundaries

| Boundary | Trusted side               | Untrusted side                                       |
| -------- | -------------------------- | ---------------------------------------------------- |
| Network  | Hermes host over TLS       | Network path, other hosts                            |
| Electron | Main process               | Renderer (displays agent output), web content        |
| Android  | App process, Keystore      | Other apps, the system browser's pages               |
| Web      | Hermes same-origin session | Other origins, injected content                      |
| Content  | Cindl code                 | Everything Hermes relays from tools, web pages, mail |

## Threats and mitigations

| Threat                                                                    | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                             | Status                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Token theft from renderer or web storage                                  | Tokens only in Electron main (`safeStorage`) or Android secure storage; web uses Hermes's HttpOnly cookie; lint forbids browser storage outside the preferences module                                                                                                                                                                                                                                                 | Lint in place; desktop main-process storage implemented and tested (memory only without a real keyring); Android pending (PR #4)                                                                                           |
| Code interception in native sign-in                                       | PKCE S256, random `state` compared in constant time, loopback IP literal redirects only, single-use code                                                                                                                                                                                                                                                                                                               | Helpers + tests in place; live flow pending                                                                                                                                                                                |
| Ticket leakage via logs or URLs                                           | Ticket in WS subprotocol, not URL; diagnostics only through `redactText`/`redactValue`                                                                                                                                                                                                                                                                                                                                 | Desktop WebSocket factory sends the ticket only as a subprotocol and is tested (`apps/desktop/test/websocket.test.ts`); redaction gaps are being closed with the transport (PR #2)                                         |
| Compromised renderer calls dangerous Hermes methods                       | No passthrough; allowlisted `clientOps`; main re-validates arguments and sender                                                                                                                                                                                                                                                                                                                                        | Desktop implemented and tested: preload exposes only window.cindlDesktop; main checks the sender frame and the contract schema on every call (`apps/desktop/test/ipc.test.ts`, smoke spec)                                 |
| Prompt-injected agent output exfiltrates data                             | No raw HTML; remote and relative images never loaded (CSP `img-src 'self' data: blob:`); every link shows its destination host as text                                                                                                                                                                                                                                                                                 | Implemented in web with component tests; Android in progress                                                                                                                                                               |
| Compromised desktop renderer reaches the network                          | CSP `connect-src 'none'`; the renderer's session cancels every http(s)/ws(s) request and sends anything else to a dead proxy; WebRTC removed from the top frame                                                                                                                                                                                                                                                        | Desktop implemented and smoke-tested. Known gap: a same-origin `about:blank` child frame still has WebRTC (Electron runs no preload there), which can open TCP to loopback (mainly port probing); see `clients/desktop.md` |
| Approval replay or wrong action approved                                  | Requests keyed by Hermes request id; answered once, with an offered choice, through an acknowledged path; buttons lock on the first click; no standing grants or `all`. Connection epochs only move forward: a stale frame changes nothing, a re-send on a newer connection reopens the request (Hermes re-sends only open ones), and each outcome event names its attempt (contract v4, reference/server-requests.md) | Contract v4 with reducer tests for reorders around reconnects; live validation pending                                                                                                                                     |
| Cindl closes requests meant for the owner's other Hermes clients          | Cindl sends nothing for requests it does not handle: no blanket error, no decline. The one exception is the 4404 "not shown" vote for a prompt another app's window owns, sent only on a sidecar socket that counts such votes. They stay open and answerable elsewhere (ADR 0005)                                                                                                                                     | Decided; adapter implementation and two-client tests in progress                                                                                                                                                           |
| Owner edit clobbers a newer version                                       | `expectedVersion` SHA-256 check before SOUL and skill writes; memory entries are written and deleted only by their fingerprinted id, which Hermes refuses once the entry changed (positional ids are refused); diff review and explicit confirmation for every edit; deletes warn that Hermes keeps no backup                                                                                                          | Implemented in UI and synthetic scenario; Hermes path pending; race window documented                                                                                                                                      |
| Path traversal / arbitrary file access                                    | No generic filesystem operations in the client surface; memory entries only via fingerprinted learning-node ids, never filesystem routes                                                                                                                                                                                                                                                                               | By design                                                                                                                                                                                                                  |
| Resubmitting a prompt twice after a dropped connection                    | Uncertain submissions are never retried automatically                                                                                                                                                                                                                                                                                                                                                                  | Contract in place; implementation pending                                                                                                                                                                                  |
| Using Hermes's loopback per-process token (readable by any local process) | Cindl supports only login mode (native PKCE or same-origin session); it never fetches or stores that token                                                                                                                                                                                                                                                                                                             | By design                                                                                                                                                                                                                  |
| Secrets typed into chat, or a reply stored as a secret                    | Cindl never asks for credentials. It never replies to sudo, secret or vault prompts: a decline or error can become the stored secret or the password Hermes uses. They are shown read-only for another Hermes surface to answer (ADR 0005)                                                                                                                                                                             | Decided; enforced in the web UI and the demo client. Adapter tests with synthetic callbacks only are on the transport branch (PR #2); never real secrets                                                                   |
| Remote control beyond the agent's screen                                  | Display scope is one profile's agent-owned screen; leases are explicit and server-filtered; viewing never starts a screen                                                                                                                                                                                                                                                                                              | Contract in place; implementation pending                                                                                                                                                                                  |
| Public repository leaks private data                                      | Synthetic fixtures only; `.gitignore` excludes runtime data; `scripts/check-privacy.mjs` in `pnpm verify` and CI; screenshots reviewed by hand before publishing                                                                                                                                                                                                                                                       | Automated scan in place; screenshot review stays manual                                                                                                                                                                    |
| Supply chain                                                              | Exact versions, one lockfile, pnpm install-script allowlist, minimum release age, pinned CI actions (pending)                                                                                                                                                                                                                                                                                                          | Partly in place                                                                                                                                                                                                            |

## Out of scope

Compromise of the Hermes host itself, and the owner's own devices' operating
systems. Cindl cannot make Hermes's operator-level session least-privilege.
