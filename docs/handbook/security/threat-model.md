# Threat model

## Assets

- Hermes sessions and tokens (operator-level access to the agent).
- Conversation content, tool arguments and results, SOUL.md, skills, memory
  metadata, routines.
- Control of the agent-owned computer.
- The owner's attention: approvals must not train them to click through.

## Trust boundaries

| Boundary | Trusted side               | Untrusted side                                       |
| -------- | -------------------------- | ---------------------------------------------------- |
| Network  | Hermes host over TLS       | Network path, other hosts                            |
| Electron | Main process               | Renderer (displays agent output), web content        |
| Android  | App process, Keystore      | Other apps, the system browser's pages               |
| Web      | Hermes same-origin session | Other origins, injected content                      |
| Content  | Cindl code                 | Everything Hermes relays from tools, web pages, mail |

| Token theft from renderer or web storage                                                 | Tokens only in Electron main (`safeStorage`) or Android secure storage; web uses Hermes's HttpOnly cookie; lint forbids browser storage outside the preferences module                                                                                                                                                                                                                                                                                                                                                                                                                                 | Lint in place; desktop main-process storage implemented and tested (memory only without a real keyring); Android: tokens in the Keystore under the adapter's `NativeAuth` key; the sign-in attempt marker holds no verifier, state or code, and an earlier build's verifier record is deleted on first start (Node-tested; no device run); desktop: once the keyring refuses to encrypt, tokens stay in memory only for the rest of the run, the window warns, and earlier encrypted records are deleted (switching Hermes also deletes the previous origin's, retried at the next start if the disk refuses) (`apps/desktop/test/signin.test.ts`) |
| A page on another site frames Cindl's web pages (clickjacking a decision card)           | The mount sends `frame-ancestors 'none'` with Cindl's pages; Hermes's session cookie is `SameSite=Lax`, so a framed copy on another site has no session                                                                                                                                                                                                                                                                                                                                                                                                                                                | The header is the mount's job ([Running Cindl](../operations/index.md#serve-the-web-client-from-the-hermes-origin)); the cookie attribute is read from the pinned Hermes v0.22.5 source, not observed live                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| A copy of the owner's Hermes session cookie                                              | The cookie is HttpOnly and `SameSite=Lax` (and `Secure` over https); Cindl never reads it; "Sign out on this device" asks Hermes to clear it in that browser                                                                                                                                                                                                                                                                                                                                                                                                                                           | What Hermes v0.22.5 revokes depends on its provider: basic, Nous and drain revoke nothing, so a copy keeps working until it expires (basic: 12 hours access, 30 days refresh); self-hosted OIDC asks its identity provider to revoke the refresh token when it supports revocation, and the access token still works until it expires. Not fixable in Cindl. Other Cindl tabs follow a sign-out at once. An open tab keeps this browser's session in use (its 15 s check lets the gate renew the cookies while the sign-in renews them); closed tabs leave the cookies valid until they expire, and only a sign-out clears them                    |
| A crafted link to Hermes's sign-in page sends the owner to another site after signing in | Cindl builds `next` only from its own mount and the view, and refuses backslashes and control characters (`isSafeNextPath` in `@cindl/hermes-adapter`)                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Upstream: Hermes v0.22.5's `is_safe_next_path` accepts `/\host` and a path with a tab before the host, which browsers resolve to another site, so a crafted link straight to Hermes's `/login` works without Cindl. Worth an upstream report; none filed                                                                                                                                                                                                                                                                                                                                                                                           |
| Other pages on the Hermes origin (Hermes's own app, anything else served there)          | Cindl keeps nothing in browser storage but its preferences; the operator serves nothing else on that origin that is not trusted like Hermes ([Running Cindl](../operations/index.md#serve-the-web-client-from-the-hermes-origin))                                                                                                                                                                                                                                                                                                                                                                      | By design: pages on one origin share cookies, storage and script reach. Hermes's own app keeps state there too, for example `sessionStorage` `hermes.lastLocation` and its terminal's attach token. Any page there can post to Cindl's `cindl.session` channel; a message only makes open Cindl tabs ask Hermes whether their session still works                                                                                                                                                                                                                                                                                                  |
| Code interception in native sign-in                                                      | PKCE S256, random `state` compared in constant time, loopback IP literal redirects only, single-use code                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Helpers + tests in place; live flow pending                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Ticket leakage via logs or URLs                                                          | The gateway ticket rides in the WS subprotocol, not the URL. One exception, by Hermes's design: the screen socket takes its single-use display ticket (it expires after 30 s) in the query string, because noVNC cannot set a header or a subprotocol. Cindl opens that socket only inside the client implementation: desktop main, never its renderer. The web client, served from the Hermes origin, holds the ticket briefly in the page, which already holds the session that can mint one (ADR 0012). Diagnostics pass only through `redactText`/`redactValue`, which redact `display_ticket` too | Desktop main sends the gateway ticket only as a subprotocol and opens the screen socket only on the signed-in origin with the ticket as its only query (`apps/desktop/test/websocket.test.ts`); a packaged smoke test checks no display ticket reaches the window; `display_ticket` redaction and the privacy scan's rule are tested (`packages/hermes-adapter/test/redact.test.ts`, `scripts/test/check-privacy.test.mjs`). The web client opens its sockets only on the page's own origin, and nothing it keeps reaches browser storage (`apps/web/e2e/live.spec.ts`, against the fake Hermes)                                                   |
| Compromised renderer calls dangerous Hermes methods                                      | No passthrough; allowlisted `clientOps`; main re-validates arguments and sender                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Desktop implemented and tested: preload exposes only window.cindlDesktop; main checks the sender frame and the contract schema on every call (`apps/desktop/test/ipc.test.ts`, smoke spec)                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Prompt-injected agent output exfiltrates data                                            | No raw HTML; remote and relative images never loaded (CSP `img-src 'self' data: blob:`); every link shows its destination host as text                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Implemented in web with component tests; Android: native Markdown with the same rules, unit-tested (`apps/android/test/markdown.test.ts`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Compromised desktop renderer reaches the network                                         | CSP `connect-src 'none'`; the renderer's session cancels every http(s)/ws(s) request and sends anything else to a dead proxy; WebRTC removed from the top frame                                                                                                                                                                                                                                                                                                                                                                                                                                        | Desktop implemented and smoke-tested. Known gap: a same-origin `about:blank` child frame still has the WebRTC API (Electron runs no preload there). Measured in the smoke test and under strace: its TCP reaches only the dead proxy, loopback included, and it sends no UDP; the dead proxy, its `<-loopback>` rule and the IP-handling policy contain it, each checked by behaviour; see `clients/desktop.md`                                                                                                                                                                                                                                    |

| Secrets typed into chat, or a reply stored as a secret                                   | Cindl never asks for credentials. It never replies to sudo, secret or vault prompts: a decline or error can become the stored secret or the password Hermes uses. They are shown read-only for another Hermes surface to answer (ADR 0005)                                                                                                                                                                                                                                                                                                                                                             | Decided; enforced in the web UI and the demo client. Adapter tests use synthetic callbacks only (`packages/hermes-adapter/test/server-requests.test.ts`); never real secrets                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Remote control beyond the agent's screen                                                 | Display scope is one profile's agent-owned screen; leases are explicit and server-filtered; viewing never starts a screen. ## Out of scope

Compromise of the Hermes host itself, and the owner's own devices' operating
systems. Cindl cannot make Hermes's operator-level session least-privilege.
